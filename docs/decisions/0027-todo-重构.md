# ADR 0027 — ToDo 重构：删 Mock + 可读中文标题 + 类型/来源 + 学校垃圾过滤 + 60 天冷启动

> 状态：✅ 已落地（typecheck / lint / test / build 全绿）
> 日期：2026-08-23
> 前置：ADR 0022（必读=邮件驱动、草稿免审批）、ADR 0026（首页天气/晨报轮播/邮件 ToDo 抽取折叠进已有 classify）

## 背景

ADR 0026 把邮件驱动 ToDo 折进已有 `classify_inbox` / `classify_application_email`（零新增 LLM），跑起来后用户不满意：

1. **Mock 数据 + 不可读标题**：ToDo 里混着 mock-provider 生成的任务，且 stub 把 `email.subject` 直接塞进标题——subject 是数字/令牌时人看不懂（`跟进：1677387239`）。
2. **字段缺失**：没有类型、来源 link、截止日期标签。
3. **过滤太松**：学校群发 `[student_ips]` 也被当成 ToDo。
4. **历史邮件缺失**：想要每个账号**冷启动一次**回填历史邮件建 ToDo，之后增量维护，但开发阶段允许冷启动、需控成本。

用户已确认（AskUserQuestion）：冷启动回溯 **60 天**；`[student_ips]` 是**邮件主题前缀**（Mailman 风格，非 Gmail label）→ 按主题子串过滤即可，无需 label API。

## 改动

### A. Mock + 不可读 ToDo 一次性清理（boot 幂等）

- **`src/main/services/todo-purge.ts`**：`purgeEmailOriginTasks(taskService, applicationService)`。predicate = `sourceType='email'`（手动建的是 `assistant`/`routine`，不动）。同时清投递里的 mock/demo 行：`emailRefId` 以 `demo:`（seedDemoData）或 `mock-`（mock 邮件 messageId 前缀）开头 → `applicationService.purgeApplication(id)`，跨 active/deleted/archived 三表。
- **触发**：`container.ts` purge 之后、`startEmailSyncLoop` 之前，gated by `!settings.todo.purgeDone` → 调 purge → `writeTodo({ purgeDone: true })`。fire-and-forget IIFE。
- **取舍**：全量清 email-origin task（不只 mock）——不可读标题也来自真实邮件（stub 用 subject），只删 mock 会留下真邮件的不可读 ToDo；cold-start 回填用同一 `sourceId`（`email:<messageId>`）幂等重建（`taskService.create` by (sourceType,sourceId) 幂等）。**用户手改过的 email ToDo 标题会丢**——一次性重构可接受，记此 ADR。

### B. TaskCategory 枚举 + category/sourceLink 字段

- `constants.ts`：`TASK_CATEGORIES = ['school','job','bill','meeting','other'] as const` + `type TaskCategory`（学校/求职/账单/会议/其他）。
- `types.ts`：`Task` + `TaskCreateInput` 加 `category?: TaskCategory` + `sourceLink?: string`；`EmailClassificationResult` 加 `category?: TaskCategory`；`TodoSettings` 接口（purgeDone/coldStartDone/skipTokens/coldStartEnabled/backfillBatchSize）。
- `schemas.ts`：`taskCategorySchema`；taskSchema + classificationSchema + classifyApplicationEmailOutputSchema results 补 `category`。顺手补 `sourceProvider`（行映射早有、schema 漏）。
- DDL/迁移：`schema.ts` tasks 表加 `category` + `source_link` 列；`client.ts` `applyGuardedAlters` 加 `addColumnIfMissing('tasks','category','TEXT')` + `('tasks','source_link','TEXT')`（M1 ALTER IF NOT EXISTS 幂等 pattern）；`sqlite-store.ts` row mapper + insert/update 透传；`in-memory-store.ts` 同步。

### C. 可读中文 todoTitle（修 stub + LLM 指令）

- `agent-runtime.ts` classifyInbox stub（**用户投诉根因**）：绝不内嵌 `email.subject`。`const who = email.from.name ?? email.from.address ?? '发件人'`；`todoTitle: isFollowUp ? \`跟进 ${who}（${topicLabel}）\` : \`回复 ${who}（${topicLabel}）\``。`TOPIC_LABELS`（fees_billing→账单/recruiting→求职/meeting→会议/ads→广告/general→通知）。
- classifyApplicationEmail stub 已可读（`${company} 面试 · ${position}`），补 `category:'job'`。
- `prompt-injection.ts` classify_inbox / classify_application_email task 分支加指令：todoTitle 必须 ≤20 字中文动作描述，概括要做的事，禁止直接复制邮件主题；外文专有名词可保留英文；仅在确有可执行下一步时填；让模型填 `category`。

### D. category 赋值（LLM 填 + stub 确定性兜底）

- classifyInbox stub：`categoryFromTopic(topic)`——fees_billing→bill、recruiting→job、meeting→meeting、其余→other。`school` 留给 LLM（stub 无可靠学校信号，兜底 other）。
- classifyApplicationEmail stub：恒 `'job'`。
- `enforceTrust` untrusted 分支：`category: undefined` + 剥 `category`（§17）。

### E. `[student_ips]` 主题子串过滤（零 LLM，§17-safe）

- `bulk-mail.ts`：`DEFAULT_SKIP_TOKENS = ['[student_ips]']`；`isSchoolSpam(email, tokens)`——subject 小写 includes token 小写。
- 折进 pre-LLM 闸：`email-briefing-service.briefNewEmails` 顶部 `realEmails = newEmails.filter(!isSchoolSpam)`（bulk 循环 + humanEmails 都用 realEmails）；`application-service` funnelEmails 加 `&& !isSchoolSpam`。tokens 经 deps 注入（来自 `settings.todo.skipTokens`，默认 `['[student_ips]']`）。
- 可配：集成与设置页「邮件待办设置」skip-token 编辑器。

### F. sourceLink

Gmail：`email.sourceUrl`（`https://mail.google.com/mail/u/0/#all/<id>`）直传。163：无 web deep link → `undefined`，UI 只显 `163` 徽章（不造假链接）。Home ToDo 卡：sourceLink 存在则把 provider 徽章包成 `<a target=_blank rel=noreferrer>`。

### G. 60 天冷启动回填

**状态独立于增量游标**：`todo.coldStartDone: string[]`（accountId 列表），不动 `EmailSyncCursor`（游标按 provider 类型键，动了会破坏增量）。

- **provider 侧**：
  - Gmail（**最高风险**）：新 `listAllSince(sinceInternalDate, maxPages=20)`——循环 `nextPageToken` 页（每页 100），累积 messageId，直到某页最老邮件 `internalDate < since` 或页数耗尽；封顶 `20×100=2000`；**不动**增量 `listMessages`（后者刻意不消费 nextPageToken）。`listBackfill(sinceDate)` 包装。
  - 163：`listBackfill(sinceDate, maxItems=2000)` 调 `listMessages({sinceHours, limit})`（IMAP search + 客户端 sinceHours 过滤已能取回）。
  - `EmailProvider` 接口加可选 `listBackfill?(sinceDate, maxItems?)`。
- **`EmailBriefingService.backfillAccount(provider, opts)`**：取 now-60d；`provider.listBackfill(sinceDate)`；pre-LLM 过滤（bulk + 学校 spam）**先**滤；分批 `batchSize`（默认 20）批，每批 ONE `classify_inbox`（复用 `briefNewEmails(batch, {skipDrafts:true})`）；`skipDrafts` → 不烧 `generate_draft_reply`；幂等（sourceId / NTK seen / 投递 sourceRef 去重）。
- **范围决策**：回填**只跑 `classify_inbox`（ToDo + 必读）**，不跑 `classify_application_email`（漏斗维持增量）——用户要的是 ToDo 冷启动，recruiting/interview 邮件会被 classify_inbox 以 recruiting topic 捕获建 ToDo；成本减半。
- **触发**：`container.ts` `triggerColdStartIfNeeded(provider)`——在 `refreshEmailProviders` 每个 real provider（gmail/mail163）确认 connected 后调用；读 `settings.readTodo()`，`coldStartEnabled !== false` 且 accountId 不在 `coldStartDone` → fire-and-forget `emailBriefing.backfillAccount` + 标记 done。断连重连需手动「重新冷启动」按钮重置。

**成本控制（显式）**：① 只过滤后邮件到 LLM；② 批 20；③ Gmail 页封顶 20；④ `coldStartEnabled` 可关；⑤ 每 accountId 一次；⑥ 只跑必读路径；⑦ skipDrafts。超 2000 封记 activity。

### H. UI + IPC

- `labels.ts`：`TASK_CATEGORY_LABEL`（school→学校/job→求职/bill→账单/meeting→会议/other→其他）。
- `Home.tsx` ToDo 卡：category 徽章；sourceLink 存在则 provider 徽章可点（Gmail only）。
- `Integrations.tsx`：「邮件待办设置」section——skip-tokens 编辑器（textarea，每行一个）、`coldStartEnabled` 开关、每账号「重新扫描」按钮。
- 新 IPC：`TODO_GET_SETTINGS` / `TODO_SET_SETTINGS` / `TODO_COLD_START`。get 返 `{skipTokens,coldStartEnabled,coldStartDone}`；set 写 `writeTodo` 并 live 推送 skipTokens 到两服务；cold-start 清该账号 `coldStartDone` + fire-and-forget 调 `backfillAccount`。非密、R1 本地读写（§15 免审批）。preload + contracts + `DaymateApi` 透传。

## 设计取舍 / 风险

- **竞态修复（boot 后发现）**：purge IIFE（写 `purgeDone`/`skipTokens`）与 cold-start trigger（写 `coldStartDone`）都是 fire-and-forget 异步，原 `writeTodo` 整块替换 → cold-start 的 read-modify-write 把 purge 写的 `purgeDone` 覆盖。后果：每次重启 `purgeDone` 又是 undefined → purge 重跑清空 email ToDo，而 cold-start 因 `coldStartDone` 已标记不再回填 → **第 2 次重启后 email ToDo 永久消失**。两处修复：① `writeTodo` 改字段级 merge（`{...current.todo, ...todo}`，部分写不覆盖其他键）；② container 里 cold-start trigger `await purgeSettled` 闸门（purge IIFE `finally` resolve），串行化。已验证重启后 5 条 ToDo 持久存活、`purgeDone` 持久。测试 `settings-todo.test.ts` pin 了 merge 行为。
- **Gmail `nextPageToken` 翻页（最高风险）**：独立 `listAllSince`，不动增量 `listMessages`；封顶 20 页×100=2000；页间 await 降速；超限记 activity。v1 可接受丢最老。
- **回填只跑必读路径**：用户要 ToDo，classify_inbox 已能捕获 recruiting/interview 邮件建 ToDo；漏斗维持增量；成本减半。
- **全量清 email-origin ToDo 一次性**：用户手改标题会丢，幂等回填重建；可接受。
- **coldStartDone 与游标分离**：不动增量游标；断连重连需手动按钮重置——H 已覆盖。
- **163 无 deep link**：sourceLink 留空，UI 只显徽章。
- **taskSchema 漏 sourceProvider**：顺手修。
- **§17**：untrusted 邮件 `enforceTrust` 仍剥 todoTitle/dueDate/category；学校 spam 在 pre-LLM 闸 deterministic 跳过。§15 不受影响（ToDo=本地写 R1；settings IPC=本地读写 R1）。
- **迁移幂等**：category/source_link 列 ALTER IF NOT EXISTS（M1 pattern）。
