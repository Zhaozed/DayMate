# 导航精简 + 必读=每日晨报 + 记忆 town 用户画像 + 去重

## Context

用户反馈左侧导航栏太杂乱、多个模块无用，给出三条要求：
1. 删 助手（空占位）/ 任务（不看）/ 审批（无审批需求）/ 动态（后台日志）4 个导航项；
2. 必读 = 每日晨报：去掉"收件箱已分类"桶计数噪音，只留 curated brief（会议/跟进/着急/
   重要）；
3. 记忆 重做：town 风格、可编辑、有用户画像、修重复。

Verified: typecheck + lint + 377 tests (1 skipped) + dev 全绿；DB 验证 必读只剩 4 条
curated 项（导师同步 urgent / 工作总结 high / 晨间简报 high / Morning Brief high），
收件箱已分类 / Inbox classified 噪音清零；记忆无同 key 重复 confirmed。

## 决策

### 1. 导航 11 → 7（休眠保留，非硬删）
NAV 删 Assistant/Tasks/Approvals/Activity 四项，剩 首页/必读/投递/面经库/例程/记忆/
集成与设置。页面组件文件保留在磁盘（休眠，镜像 BOSS 退场 ADR 0019 模式）；后端
TaskService/ActivityService/ApprovalService 全保留（例程仍创建 task、晨报读 open tasks、
机器人状态派生 activity）。

- **审批特殊处理**：删 nav 按钮 + 删主区 mount 不行（`approval-from-robot` e2e 手动触发
  Draft Review 走审批深链）→ 保留 Approvals import + mount 作休眠安全网（无 nav 按钮，
  仅机器人审批气泡深链可达；当前无 R3 外部写例程自动触发——邮件发送未开、BOSS 退役、
  Draft Review 是 manual trigger——故审批永不触发，用户看不到）。
- **不绕过 §15 自动批准外部写**——安全边界。用户"最高权限"诉求通过"无 R3 例程激活 =
  无审批触发"满足，而非破坏闸。`WORKBENCH_PAGES` 删 Assistant/Tasks/Activity（无深链用
  它们），留 Approvals（深链需要）；`active` 状态类型从 NavName 改 WorkbenchPage 让
  Approvals mount 可类型检查。

### 2. 必读 = 每日晨报（止噪 + 清存量 + 重写页）
- **止噪源头**：`auto-inbox.ts` 删 `publish` step（桶计数 NTK 噪音）；auto_inbox 仍
  create_tasks + notify，`output` 从 `'need_to_know'` 改 `'task'`。注释说明必读只收 curated
  brief，不收分类噪音。
- **清存量**：container boot `needToKnowService.deleteByTitle('收件箱已分类')` +
  `deleteByTitle('Inbox classified')`（zh-CN 标题 + 本地化前英文标题一次性迁移）。
- **页重写** `NeedToKnow.tsx`：Header「每日晨报」+「运行晨报」一键按钮 +「清空全部」reset；
  按 priority 分组（紧急→重要→待办，每组带计数+色标）；组内今日置顶 + createdAt desc；
  每条加「忽略」；空态链到运行晨报；`onActivityChanged` → refetch（NTK 无独立 push channel）。
- **新 IPC**：`NEED_TO_KNOW_DISMISS` / `NEED_TO_KNOW_CLEAR_ALL`；store 加
  `deleteAllNeedToKnow` / `deleteNeedToKnowByTitle`。

### 3. 记忆 town 用户画像 + 去重（修两个真 bug）
**重复根因**：① UI「确认」调 `updateMemory({confirmed:true})`（`handlers.ts` →
`service.update`）**绕过** `service.confirm()` 的同 key 去旧逻辑 → 同 key 多个 confirmed；
② 提案只做 exact (key,value) 去重 → 近义措辞累积成堆。

- **3a 修 confirm 绕过**：新 IPC `MEMORY_CONFIRM` → `service.confirm(id)`（含去旧）；UI
  确认改调 `confirmMemory`；`updateMemory` 仅用于纯编辑 value。
- **3b 提案去重**：`save()` 对 proposed 项加"同 key 只留最新提案"——保存新 proposed 前
  删同 key 既有 proposed（replace 非累积）；user-authored confirmed save 同理 demote 同 key
  旧 confirmed。语义：confirmed 一 key 一值（confirm 保证）+ proposed 一 key 一值（save replace）。
- **3c 存量去重**：`MemoryService.dedupe()`——每 (key, confirmed) bucket 留最新一条删
  其余；container boot 调一次（清历史重复，镜像 NTK 清存量）。
- **3d 页重写** `Memory.tsx`：town 风格分组——**用户画像区**（persona/writing_style/
  email_tone/working_hours/job_search_profile/meeting_duration 每键一行 inline 编辑 +
  未设置可添加）+ 联系人/项目/通知偏好区 + 其他记忆区 + 待确认区（确认走 confirmMemory）+
  新建卡。`labels.ts` 加 `MEMORY_KEY_LABEL` + `PROFILE_MEMORY_KEYS`/`LIST_MEMORY_KEYS`。

## 关键决策要点
- **休眠非硬删**（镜像 ADR 0019 BOSS 退场）——删 nav 按钮，组件文件 + 后端 service 保留；
  一行挂回即可恢复。审批更甚：连 mount 都留（e2e 深链安全网）。
- **§15 闸不破坏**——用户"最高权限"=无 R3 例程激活→无审批触发，非自动批准外部写。
- **止噪在源头不在页过滤**——auto_inbox 删 publish step 是根治；页端按 title 过滤是 hack，
  不做。清存量用一次性 boot deleteByTitle（精确标题，非长期过滤）。
- **必读无独立 push channel**——用 `onActivityChanged` 触发 refetch（activity 变 = 例程
  跑了 = 可能有新 NTK）。
- **记忆 dedupe 用 listMemory DESC + 首见保留**——两 store 都按 createdAt DESC 返回，
  首 (key,confirmed) bucket 首见即最新，删其余。简单确定性，无 fuzzy。
- **MEMORY_KEYS 的 one-confirmed-per-key 语义保留**——contact/project 也是一 key 一值
  （confirm demote 保证）；不扩成多值（改 schema 是更大改动，本里程碑不做）。

**Deferred**：联系人/项目多值（需破 one-per-key 语义 + schema）；必读历史趋势（需 NTK
时序持久化）；记忆批量导入；审批页彻底删（若用户日后确认永不恢复 Draft Review）。
