# 0018 — 岗位推荐双桶重做（校招生实习 + 秋招正职双投）

Date: 2026-08-11

## Context

Milestone C 的「岗位推荐」面向社会招聘人群设计。用户是校招生，实习 + 秋招双投，
提了六个具体不满：

1. **给的是社会招聘岗位** —— 服务层 `fetchJobRecommendations` 只把 `keyword` +
   `cities[0]` 传给 `boss search`，**没传 job-type/experience/degree 过滤**，boss 返回
   混杂社招，评分无法纠正。校招生拿到一堆「3-5年经验」的社招岗，不合适。
2. **只能抓 15 条** —— 单页 search（page 1 = 15），无翻页。
3. **速度很慢** —— boss-cli 内置反爬延迟（Gaussian jitter + 5% 长停顿）是必要的；
   并发抓取会触发限流（实测：接入期连续 CLI 探测已把 `__zp_stoken__` 触发限流失效）。
   「快」和「多」要靠**渐进式加载**，不能自动多页并发。
4. **低匹配不让投递** —— 转投递按钮被 `r.recommend` 闸住，低匹配岗位无按钮。
5. **多城市填不上** —— 城市是单文本框 split（`北京、上海`），且经验/学历是自由
   文本输入，用户要「选择框」。
6. **没有实习/校招分栏** —— 用户要分桶 + 标签页切换。

boss-cli 滤器已验证支持双桶：`JOB_TYPE_CODES={全职:1901,实习:1902}`，
`EXP_CODES["在校/应届"]=108`，`DEGREE_CODES`，`CITY_CODES`（top 12 + 更多）。

## Design（用户确认的 UX）

- 城市用**常用城市复选网格**（top 12 + 「更多」展开，取自 boss-cli `CITY_CODES`）。
- 布局用**标签页切换**（segmented tabs [实习]/[秋招正职]，一次看一桶）。
- 学历用**下拉框**（`DEGREE_CODES`：不限/大专/本科/硕士/博士）。
- 经验栏**移除** —— 桶隐含：实习桶无 exp 过滤；秋招正职桶 `--exp 在校/应届`。
- 转投递按钮**始终显示**；低匹配（tier low/skip）旁注「低匹配」灰字提示。
- 「加载更多」每桶独立，基于 `hasMore`。

## 架构原则（关键决策）

**bucket 是确定性业务规则，不是 agent 推理（§12）。** `score_job_matches` agent
**保持 bucket 无感知** —— 不改其 Zod/TypeBox/stub/prompt/real-path branch（不动
6-touchpoint lockstep）。服务层负责：按桶发不同 boss search（job-type/experience）、
一次打分调用（全量 jobs 合并）、按 securityId 把结果拆回两桶。新增 `bucket` 字段
只存在于**服务→renderer 的 IPC 类型**（`JobRecommendations`），不进 agent 输出 schema。

这与 `0011` 的「匹配是 service 确定性逻辑，非模型」一脉相承：模型只评分+提取，
service 决定分桶（确定性）。

## 实施

### shared 类型（`src/shared/types.ts`）
- `JobMatchResult` / `JobMatchOutput` / `JobMatchInput` / `JobIntent` —— **不改**
  （agent 输入/输出，不动 lockstep）。
- 新增 `JobBucket = 'intern' | 'campus'` + `JobRecommendations`（title/summary/reason/
  priority + `intern: JobMatchResult[]` + `campus: JobMatchResult[]` + `error?` +
  `internHasMore`/`campusHasMore`）。
- `FetchJobRecommendationsOpts = { bucket?: JobBucket; append?: boolean }`：无参 = refresh
  （抓两桶 page 1，重置缓存）；`{bucket, append:true}` = 抓该桶下一页，并入缓存。
- `DaymateApi.fetchJobRecommendations` 签名改：`() => JobMatchOutput` →
  `(opts?: FetchJobRecommendationsOpts) => JobRecommendations`。

### boss-cli provider（`boss-cli-provider.ts`）
- 新增 `searchJobsPaged(query): Promise<{ jobs; hasMore }>` —— 透传 boss envelope 的
  `data.hasMore`（`search.py` `_render` 用 `data.get("hasMore")`）。旧 `searchJobs`
  保留为 thin wrapper（`boss.search` tool / routine preset 不分页，不破坏）。
- `BossProvider` 接口 + `SwappableBossProvider` + `MockBossProvider` 三处加
  `searchJobsPaged`（mock 分桶：见下）。

### 服务层（`application-service.ts` `fetchJobRecommendations`）
重写为双桶 + 多城市 + 分页 + 限流友好：
- 新增成员：`lastPage: {intern:0, campus:0}`、`lastResults: {intern:[], campus:[]}`、
  `lastHasMore`、`internSecurityIds`/`campusSecurityIds`（拆分用，复用既有 `lastJobs` 缓存）。
- **`searchOneBucket(bucket, intent, cities, page)`**：顺序遍历 cities（**不并发 —— 反爬**），
  对每城调 `bossProvider.searchJobsPaged`。实习桶 `{keyword, jobType:'实习', city, degree, page}`；
  校招桶 `{keyword, jobType:'全职', experience:'在校/应届', city, degree, page}`。按 securityId
  去重（同一岗位可能在多城出现）。
- **refresh**：清缓存、`lastPage` 归零、抓两桶 page 1。
- **append(bucket)**：`lastPage[bucket]++`，抓该桶下一页，并入 `lastResults[bucket]`。
- **评分一次**（agent bucket 无感知）：`{intent, jobs: newJobs}` → `runAgentStep('score_job_matches')`
  → 按 securityId 拆回两桶（`internSecurityIds.has(sid)` 判断）。
- **限流处理**：catch `BossCliError` code `not_authenticated`/`rate_limited` → 记
  `provider_unavailable` Activity + 设 `error` 字段，**已抓到的部分仍返回**（镜像 email
  provider 宕机优雅降级）。其他错误 propagate。
- append 时只对新抓的 jobs 评分，合并进对应桶；每桶 recommend-first + score-desc 重排。

### Mock boss provider（`mock-boss-provider.ts`）
- `searchJobsPaged` **按 `jobType` 分桶**返回不同 securityIds 的 fixture：`jobType==='实习'`
  → INTERN_JOBS（薪资 `元/天` 风格）；`jobType==='全职'` → CAMPUS_JOBS（薪资 `K` 风格）；
  无 jobType → 全部（legacy `boss.search` tool / routine preset 路径，既有 preset 测试不受影响）。
  这是让双桶拆分在测试中**可观测**的关键 —— 否则两桶拿到相同 sid 会全部塌进 intern 桶。
- `hasMore`：match set 超 slice 或 `page > 1` 且有结果时为真（模拟分页，让 append 路径可测）。

### Renderer（`Applications.tsx` `JobRecommendationSection`）
全量重写 UI：
- **求职意向表单**（可折叠）：keyword text + **城市复选网格**（POPULAR_CITIES top 12 +
  MORE_CITIES 「更多」展开，取自 boss-cli `CITY_CODES`）+ salaryMin/Max number + **学历
  select**（DEGREE_OPTIONS）。**移除经验栏**（桶隐含）。保存时 `experience: undefined`
  清除任何存量值。
- **抓取**：`fetchJobRecommendations()`（refresh），loading 文案「抓取中…（顺序抓取，稍候）」
  告知用户顺序抓取是反爬必需。
- **标签页切换**：`tab: 'intern'|'campus'`，segmented `[实习 (N)] [秋招正职 (N)]`，主区只渲
  当前桶。
- **岗位卡**：company · jobName · tier 徽标 + score · salary/city/reasons。**转投递按钮始终显示**
  （去掉 `r.recommend &&` 闸）；低匹配（tier low/skip）按钮旁注「低匹配」灰字。点击
  `convertJobToApplication(sid)`。
- **加载更多**：每桶列表底「加载更多」按钮（`results[tab+'HasMore']` 为真时显示）→
  `fetchJobRecommendations({bucket: tab, append:true})`，结果并入。
- **error 态**：`results.error` 时显示 amber 提示条（限流/登录态失效）。

### labels（`labels.ts`）
加 `JOB_BUCKET_LABEL = { intern: '实习', campus: '秋招正职' }`（wire id `intern`/`campus`
保持英文，显示中文，镜像既有 localisation 约定：标识符不译、只译显示）。

### IPC + preload
- `JOB_RECOMMENDATIONS_FETCH` handler 读 jobIntent（settings）+ `opts`（renderer 传），
  调 `applicationService.fetchJobRecommendations(agentRuntime, jobIntent, opts)`。
- preload `fetchJobRecommendations(opts?)`。
- 返回类型 `JobRecommendations`。

### 测试（`tests/integration/job-recommendation.test.ts`）
新增 4 个 dual-bucket service 测试（保留既有 2 个 routine preset 测试不变）：
- **双桶拆分**：intern/campus 各有结果，securityId 不交叉；实习桶含 `元/天` 薪资，校招桶含 `K`。
- **append 累加**：load-more 并入 intern 桶，campus 不变，桶内无重复 sid。
- **限流部分结果**：`RateLimitBossProvider`（第 N 次 searchJobsPaged 抛 `BossCliError('rate_limited')`）
  → `error` 字段含「限流」，实习桶（先抓）仍有结果。
- **低匹配可转投**：任意结果（不分 tier/recommend）可 convert；二次 convert 幂等不重复。

## 关键决策

- **bucket 是确定性业务规则，agent bucket 无感知** —— 镜像 `0011`「匹配是 service
  确定性逻辑非模型」；service 分桶，agent 只评分。不动 6-touchpoint lockstep。
- **顺序抓取不并发** —— 反爬实测：并发/连续探测会触发 `__zp_stoken__` 限流失效
  （不可由代码修复，是 boss-cli 的反爬约束）。顺序遍历 cities + 渐进加载是诚实的设计，
  不额外加延迟（避免过度工程；boss-cli 已内置 jitter/退避）。
- **`searchJobsPaged` 新增而非改 `searchJobs` 返回结构** —— 旧 `searchJobs` 是
  thin wrapper，`boss.search` tool / routine preset 不分页，不破坏既有契约。
- **mock 按 `jobType` 分桶** —— 让双桶拆分在测试中可观测；既有 preset 测试走「无 jobType」
  legacy 路径不受影响。
- **转投递不闸 recommend** —— 用户要能投低匹配岗（自己决定）；低匹配旁注提示而非禁用。
- **经验栏移除** —— 桶隐含（校招桶=在校/应届）；避免用户手填与桶语义冲突。
- **城市复选网格 vs 文本框** —— 用户明确要「选择框」；top 12 + 展开覆盖常用，避免 40+
  城市一次铺满。

  蔓延；manual 双投是主路径）。
