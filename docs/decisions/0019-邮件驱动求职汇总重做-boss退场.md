# 0019 — 邮件驱动求职汇总重做 + BOSS 退场

**Status:** accepted · **Date:** 2026-08-12 · **Milestone:** post-MVP (邮件驱动求职汇总)

## 背景

BOSS 直聘反爬不可破（`0017` 验证）：camoufox 生成的 `__zp_stoken__` 被 BOSS search
拒认；真实浏览器 cookie 提取不稳；session-merge bug 已修但 search 仍不可用。用户决定
**BOSS 相关 UI 全隐藏**（后端休眠保留，可逆），投递模块 pivot 为「邮件自动汇总」：
收到招聘相关邮件 → 自动维护投递面板（回执→建 item，面试/测评/笔试→追加事件），严格
不重复、正确路由（该建就建、该追加就追加）。同时投递卡片要富展示（岗位名字在前 +
城市 + 薪资 + JD 片段），JD 尽可能补全（邮件正文抽 JD 为主 + 新 `web.fetch_jd` 工具补）。

地基已存在（Milestone A `syncFromEmails` + `classify_application_email` + locked 优先级
+ 待确认队列 + `sourceRef` 事件幂等），但缺常驻 feed、增量游标、自动建投递、normalized
item 级去重、JD 抽取/补全、卡片富展示。

用户三决策：BOSS UI **全隐藏**；自动建投递 **激进**（公司+岗位提取到就建，含 low）；
JD **现在加 `web.fetch_jd` 工具**。

## Verified

typecheck + lint + 368 tests (1 skipped) + build + 6 e2e（含 3× critical demo）全绿。

## 变更（六阶段）

### Phase 1 — 隐藏 BOSS UI（reversible，后端休眠）

纯 renderer 改动，后端（boss provider / `boss.*` 工具 / `score_job_matches` /
`job_recommendation` preset / boss IPC）全保留不动。

- `Applications.tsx`：删 `<JobRecommendationSection>` mount + `BossStatus` 横幅 +
  Header「同步 BOSS」按钮 + 相关 state/handlers。`JobRecommendationSection`/
  `BossStatus` 组件定义保留为 `export function`（dormant，便于恢复；export 满足 tsc
  noUnusedLocals）。
- `Integrations.tsx`：删 `<BossCard />` mount（保留 dormant）+ `JobSearchCard` 内
  jobIntent 子块 + 相关 state/常量。**保留** `baseResumePath` +
  `transcriptTemplatePath`（AI 简历/面经仍用）。

### Phase 2a — 增量游标（per-provider 高水位，非密 settings）

- `src/shared/types.ts` `EmailQuery` 加 `sinceUid?: number`（163 IMAP UID）+
  `sinceInternalDate?: number`（gmail internalDate ms）。新 `EmailSyncCursor`
  接口。
- `mail163-provider.ts`：`sinceUid` → `imap.search` 后客户端 `filter(uid > sinceUid)`
  （UID 服务端已排序）。`messageId = String(uid)` 以便 service 推进游标。
- `gmail-provider.ts`：`listMessages` 在 `sinceInternalDate` 命中时 early-break
  （Gmail list 返回 newest-first，到游标即停，不重复抓已处理邮件）。
- `mock-email-provider.ts`：`sinceUid`（numeric messageId）+ `sinceInternalDate`
  in-memory 过滤。
- `settings.ts`：`EmailSyncSettings`（`enabled?`/`intervalSec?`/`cursor?`）+
  `readEmailSyncConfig()`（默认 enabled true / intervalSec 180 / min 60）+
  `readEmailSyncCursor()`/`writeEmailSyncCursor()`（merge，保留 enabled/interval）+
  `normalizeEmailSync()`（坏游标/interval 丢弃；坏游标 = 从零重扫，`sourceRef` 幂等兜底）。

**关键决策**：`unreadOnly` **不再强制 true**——用户可能在邮件客户端先读了邮件；游标
（UID / internalDate）是唯一的「已处理」闸。agent 只在有新邮件时跑（空周期近零成本）→
cadence 可 180s。

### Phase 2b — 容器常驻 poll loop（镜像运势 cron）

- `container.ts`：boot 后 `startEmailSyncLoop()`：读 `intervalSec` →
  `setInterval(tick, intervalMs)`。`tick`：读 `enabled`（每轮重读，可 live 切关）→
  读 cursor → `applicationService.syncFromEmails(emailProviders, agentRuntime, cursor)` →
  `writeEmailSyncCursor(result.cursor)` → 有变更时 `broadcastApplications()` +
  `broadcastEmailMatches()`。每轮 try/catch，失败记 `provider_unavailable` Activity
  不杀 loop。首 tick 延迟 10s 不阻塞启动。

**关键决策**：feed 放 **container 不放 scheduler**——镜像 Milestone E 运势 cron
（容器已有全部 deps；放 scheduler 要加构造参数污染其职责）。**独立于 scheduler pause**
（邮件是主 feed，不应随 routine pause 停；用户经 settings 关）。

### Phase 2c — `classify_application_email` + jdExcerpt/city/salary（6-touchpoint）

6-touchpoint lockstep 加三个 optional 输出字段（`jdExcerpt?`/`city?`/`salary?`）：
1. Zod `schemas.ts`：`results[]` 加三 optional。
2. TypeBox `structured-output.ts`：mirror。
3. TS `agent-runtime.ts` `ApplicationEmailResult`：加三 optional + JSDoc。
4. Stub：新 `extractJdExcerpt`（正则抽「岗位职责/描述/任职要求/JD/Description」后 ≤200
   字片段）+ `extractCity`（23 个一线/新一线城市名匹配）+ `extractSalary`
   （`20-40K`/`20K` 正则）。三者在 stub + real-LLM 路径同构。
5. Prompt `prompt-injection.ts`：task 串加「若邮件含 JD 片段/城市/薪资，抽入
   jdExcerpt/city/salary（无则省略）」。
6. `enforceTrust`：untrusted 邮件 `delete jdExcerpt/city/salary`（§17——不把
   untrusted prose 或 untrusted 派生猜测带进投递记录）。

**关键决策**：jdExcerpt 是主（邮件正文常带 JD 片段），city/salary 是 bonus（邮件常有
城市、少有薪资）。三字段是「邮件能补的都补」，与 Phase 4 `web.fetch_jd`（公网补）
互补。

### Phase 2d — 路由规则 + 自动建投递 + normalized 去重（service 确定性，激进）

重写 `syncFromEmails` 签名加 `cursor: EmailSyncCursor` 参数，返回加 `created` +
`cursor`。路由：

```
for each non-untrusted result r with company && position:
  match = findApplicationByNormalized(company, position)   # normalized 去重
  if match: appendEmailEvent(match.id, r, email)          # 追加事件
  else:     # 激进：未命中也建
    app = create({company, position, source:'email', city?, salary?, jdText?, })
    updateApplication(app.id, {emailRefId: r.messageId})   # 直链种子
    appendEmailEvent(app.id, r, email)
for each r with !company || !position:  pushPending        # 无身份，建不了
for each untrusted r: skip                                # §17
```

- `findApplicationByNormalized(apps, company, position)`：normalized exact（company
  AND position）。**无 fuzzy 子串兜底**——用户可能在同一公司投多个岗位，company-only
  子串命中会错误合并两个不同投递。未命中 → 激进建。
- `normalizeCompany`/`normalizePosition`（lowercase + 去公司后缀 `有限公司/科技/集团/
  Inc./Ltd./...` + 去岗位噪音 `资深/高级/工程师/...` + collapse whitespace）。
- `appendEmailEvent` 扩展：若 `r.jdExcerpt`/`r.city`/`r.salary` 且对应字段空 →
  `updateApplication` minimal patch（R1 本地写，§15 仅 gate 外部写）。**只补空字段**
  ——手动填的 JD / `web.fetch_jd` 抓的永不被邮件抽取覆盖。
- 删 `matchApplication`（tsc noUnusedLocals）——`findApplicationByNormalized` 取而代之。
- `RECRUITING_PLATFORM_DOMAINS`/`extractDomain`/`textHasEmail` 改 `export`（保留供未来
  confidence-tiered 路径；当前激进路由不查它们）。

**关键决策**：
- **激进建投递**——公司+岗位提取到就建（含 low confidence），不进待确认队列。待确认
  队列只收「缺公司或岗位」的邮件（无身份，建不了）。用户决策「全部自动建」。
- **normalized item 级去重是 sourceRef 的安全网**——`sourceRef` 只去重同一封邮件；
  normalized 去重跨邮件（「字节跳动有限公司」vs「字节跳动」+同岗位）。
- **无 fuzzy 兜底**——镜像用户「多岗位同公司」需求；未命中即建，per-event `sourceRef`
  仍防同封邮件重复事件。

### Phase 3 — 投递卡片富展示 + detail「搜索 JD」按钮

- `Applications.tsx` `ApplicationCard` headline 重构：**position 在前**（`text-sm
  font-medium`）+ company 其后（muted）+ city + salaryRange + priority 'back' 灰角标。
  新增 JD 片段行（`jdText` 截断 1 行 `line-clamp-1`）。其余（source/date/stage/stale/
  events chips）不动。
- `ApplicationDetail.tsx` `RichFields` JD 区：加「搜索 JD」按钮 →
  `window.daymate.fetchJobJd(id)` → 填 `form.jdText`（用户审查后再保存）。error 态
  amber 提示。JD 渲染保持既有 `sandbox=""` iframe（§17，web 抓的 JD 恒 untrusted）。

### Phase 4 — `web.fetch_jd` R0 工具 + on-demand IPC

- `tool-registry.ts`：新 R0 工具 `web.fetch_jd`（parameters `{company, position?}`）。
  `execute`：DDG HTML query → `ctx.webFetch` → `extractSnippets` → plain-text join。
  新 `WebFetch` 类型（`(input: string) => Promise<string>`，mirror GmailFetch/FeishuFetch，
  type query 避 bare globals）+ `extractSnippets`（解 `<a class="result__snippet">`，
  stripTags 去标签 + 解码常见 entity，fallback `<p>/<li>`）+ `stripTags` helper。
- `ToolContext` + `EngineDeps` 加 `webFetch?: WebFetch`（optional，镜像 `settings?` 先例
  ——既有 8 个集成测试最小 EngineDeps 字面量无需改即编译）。`buildContext` 透传。
- `container.ts`：`webFetch = (input) => net.fetch(input).then(r => r.text())`
  （proxy-aware，镜像 Gmail/OAuth）。接线进 `EngineDeps` + 暴露给 on-demand handler。
- **on-demand IPC**（不经 routine engine，镜像 `generateResume`/`generatePrepMaterial`
  先例）：`APPLICATION_FETCH_JD` channel → handler 取 app.company/position →
  `toolRegistry.execute('web.fetch_jd', {company,position}, ctx)`（handler 内联构建
  ToolContext）→ `updateFields(id, {jdText})` → `broadcastApplications()`。
- preload `fetchJobJd(id)` + `DaymateApi.fetchJobJd` 返回 `{jdText, error}`。

**关键决策**：
- **`web.fetch_jd` 是确定性 R0 tool step，非 model-callable**——M3 设计「模型永不调
  Tool Registry 工具」未变。模型只分类+提取；service 用规则决定建/追加。JD 文本恒
  untrusted → `sandbox=""` iframe 渲染（§17）；`extractSnippets` 额外 stripTags 使存储
  值为纯文本（纵深防御）。
- **on-demand 不自动**——web 质量不稳（DDG 反爬、招聘板 JS 重），用户审查后再接受。
- **手写 DDG HTML 解析无新依赖**——§23 rule 2；`extractSnippets` 优雅降级（无
  snippet → 空 text + note「可手动粘贴」）。

## 关键决策（汇总）

1. **BOSS UI 全隐藏，后端休眠保留**——反爬不可破；UI 一行重新挂回即可恢复。后端
   `boss.*` 工具 / `score_job_matches` / preset 全保留（dormant）。
2. **feed 放 container 不放 scheduler**——镜像运势 cron；独立于 scheduler pause。
3. **增量游标 per-provider 持久化**——agent 只跑新邮件；`sourceRef` 事件级幂等作安全网。
4. **`unreadOnly` 不再强制**——游标是唯一闸；用户可能在客户端先读了。
5. **路由是 service 确定性逻辑，非模型**——模型只分类+提取；service 用 normalized
   去重 + 规则决定建/追加/入队。镜像 `0011`。
6. **激进建投递 + normalized item 级去重**——公司+岗位提取到就建；缺公司或岗位才入队。
7. **normalized 去重无 fuzzy 兜底**——用户多岗位同公司需求；未命中即建。
8. **JD 三层补全**：邮件 jdExcerpt（主，Phase 2c）→ `web.fetch_jd`（公网，on-demand，
   Phase 4）→ 手动粘贴。只补空字段，永不被后抓覆盖。
9. **`web.fetch_jd` 确定性 R0，非 model-callable**——M3 设计未变；§17 sandbox iframe +
   stripTags 双防御。
10. **6-touchpoint lockstep 扩 `classify_application_email`**——jdExcerpt/city/salary
    六处同步。
